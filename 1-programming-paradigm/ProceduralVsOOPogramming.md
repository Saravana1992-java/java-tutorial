# 🆚 Procedural vs Object-Oriented Programming

| Feature                     | Procedural Programming                          | Object-Oriented Programming (OOP)               |
|-----------------------------|--------------------------------------------------|--------------------------------------------------|
| **Approach**                | Top-down                                         | Bottom-up                                        |
| **Structure**               | Functions / Procedures                          | Objects / Classes                                |
| **Focus**                   | Logic and sequence of actions                   | Data and behavior encapsulated in objects        |
| **Data Handling**           | Separate from functions                         | Encapsulated within objects                      |
| **Security**                | Less secure (no data hiding)                   | More secure (supports encapsulation)             |
| **Reusability**             | Limited reuse                                   | High reuse via inheritance and polymorphism      |
| **Modularity**              | Function-based                                  | Object-based                                     |
| **Examples**                | C, Pascal, BASIC                                | Java, C++, Python, C#, Ruby                      |
| **Best For**                | Simple, linear tasks                            | Complex, scalable systems                        |
| **Extensibility**           | Hard to extend                                  | Easy to extend via inheritance and abstraction   |

> Procedural programming is like writing a recipe step-by-step.  
> Object-oriented programming is like designing a kitchen where each appliance (object) knows how to do its job.
